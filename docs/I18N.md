# Internationalization (i18n) Architecture Strategy: KisanSetu

> **Core Requirement:** India-first multilingual support without changing business logic or React component structures.

---

## 2. i18n Architecture Blueprint

```mermaid
flowchart LR
    A[Client User Selects Language] --> B[Language Context / localStorage]
    B --> C[i18n Translation Dictionary Loader]
    C --> D[Load public/locales/{lang}.json]
    D --> E[React Component UI Render]
    
    subgraph Fallback Pipeline
        D -- Missing Key --> F[Fallback to Hindi hi.json]
        F -- Missing Key --> G[Fallback to English en.json]
    end
```

### Key Technical Characteristics
1. **Decoupled Business Logic:** All UI components consume a unified `t(key, params)` translation helper.
2. **Dynamic Dictionary Loading:** Translation JSON files are loaded asynchronously or bundled per language to keep initial JavaScript bundle size minimal on low-end mobile devices.
3. **Typesafe Keys:** TypeScript interface enforces that translation keys match across all locale JSON files, catching missing translation strings at compile time.

## 4. How to Add a New Language (Zero Code Change)

To add a new Indian language (e.g. Odia `or` or Malayalam `ml`):

1. **Step 1:** Create file `public/locales/or.json` copying structure from `en.json` and providing translated string values.
2. **Step 2:** Register the language code in `/src/lib/i18n/config.ts`:
   ```typescript
   export const SUPPORTED_LOCALES = [
     { code: 'en', name: 'English', nativeName: 'English' },
     { code: 'hi', name: 'Hindi', nativeName: 'हिन्दी' },
     { code: 'pa', name: 'Punjabi', nativeName: 'ਪੰਜਾਬੀ' },
     { code: 'or', name: 'Odia', nativeName: 'ଓଡ଼ିଆ' }, // Newly added!
   ] as const;
   ```
3. **Step 3:** Done! The UI language dropdown immediately incorporates Odia without modifying any layout, component, or backend API.

## 5. Dynamic Database Content i18n Strategy

For dynamic backend content stored in PostgreSQL (such as crop names, announcement notices, or centre guidelines):
- Master database tables store multi-column localized fields (e.g., `name_en`, `name_hi`, `name_pa`) OR a JSONB `translations` column:
  ```json
  {
    "name": {
      "en": "Wheat (Sharbati)",
      "hi": "गेहूं (शरबती)",
      "pa": "ਕਣਕ (ਸ਼ਰਬਤੀ)"
    }
  }
  ```
- The API helper `getLocalizedField(object, field, currentLang)` dynamically picks the appropriate string with fallback to `en`.

## 6. Voice & Audio Accessibility Hooks

For farmers with low literacy:
- Integrated **Web Speech API** text-to-speech hook (`useVoiceAssistant`) that reads out key information (e.g. current token status, queue wait time, total payout amount) in the chosen language script.
